WHAT WAS THE GOAL?
------------------
Synthetic data proved our math works, but synthetic data is "too neat". To make this project genuinely useful for retail executives, we needed to feed real, messy store data into our causal pipeline.

Our goal was:
1. Obtain a large-scale real-world retail dataset containing promotional discounts.
2. Ingest, merge, and clean the data without breaking the existing causal framework.
3. Engineer features to capture true business confounders (so our AI doesn't mistake natural holiday rushes for promo impact).
4. Run the entire pipeline end-to-end and make sure all tests pass.


WHAT HAPPENED & DECISIONS I MADE AS MEET:
------------------------------------------

1. Smart Dataset Pivot:
   - We initially looked at both Criteo Uplift and Rossmann Store Sales.
   - The Criteo server was down/unavailable for download, but I didn't let that block progress. We pivoted immediately to the Rossmann dataset:
     * Over 1,017,209 daily sales rows
     * 1,115 European drug stores over 2.5 years (2013-2015)
     * Treatment column: `Promo` (whether a discount campaign ran on that day)
     * Outcome column: `Sales` (daily revenue in euros)

2. Identifying the Real Causal Confounding Problem:
   - A naive look at the data showed:
     * Non-Promo Days: average sales = $5,929
     * Promo Days: average sales = $8,228
   - That looks like a massive +$2,299 lift. BUT stores run promos on busy weekdays and paydays! If you ignore store location, competition, and calendar dates, you credit the promo for sales that would have happened anyway.
   - This real-world confounding is the EXACT problem our DML algorithm was built to solve.

3. Built `load_rossmann()` in `src/data/load_data.py`:
   - Automatically merges daily transactions (`train.csv`) with store profiles (`store.csv`).
   - Cleans the data by filtering out closed stores (`Open == 0`) and zero-sales records to remove artificial noise.
   - Handles real-world missing data safely (fills missing competition distances with median, handles missing promo2 start dates).
   - Standardizes the output to our project's schema: maps `Store` to `CustomerID`, `Promo` to `Discount`, and `Sales` to `Outcome`.

4. Engineered 17 Business Confounder Features in `src/data/features.py`:
   - Time & Calendar: Day of week, Month, Quarter, Year, Weekend indicator.
   - Store & Competition: Competition distance, Log-transformed competition distance (diminishing effect of distance), Competition active flag.
   - Store Categorization: Store types (a, b, c, d) and Assortment levels (basic, extra, extended) encoded for machine learning.
   - Created the helper `get_rossmann_feature_cols()` so downstream team members can grab the exact confounder columns with one line of code.

5. Debugged Windows Encoding & Pipeline Quality:
   - Solved a Windows cp1252 terminal encoding bug where Unicode symbols in the logger crashed on standard command prompts.
   - Created an end-to-end smoke test script: verified that loading real data, extracting features, training Double ML, and running the Knapsack budget optimizer all run smoothly without errors.
   - Re-ran our pytest suite: all 8 tests passed 100%.


KEY RESULT & TAKEAWAY:
----------------------
We now have full support for over 1 million real-world retail records! The causal engine is no longer just a theoretical classroom exercise—it is actively processing real store transactions, isolating discount effects from organic foot traffic, and optimizing real promo budgets.
